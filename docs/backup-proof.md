# Snapshot backup acceptance

The realm and persist drains retain each read-only Btrfs snapshot until a named Borg archive has been accepted. A successful create must have exit status zero; Borg warnings count as failure. Creation uses only declared static exclusions. Cache tags and `.nobackup` files cannot exclude a canonical directory.

The first archive, an archive already present when a drain starts, and the first archive after a coverage-policy change receive an independent full proof. The same proof is due at least every seven days. It enumerates canonical source and archive paths, compares file metadata, links, xattrs and ACL presence, checks archive health, and hashes regular file content on both sides. A failed or interrupted full proof leaves the snapshot and acknowledgement marker unchanged. A failed full proof does not advance the seven-day clock.

Between full proofs, a newly created archive can receive a producer-backed proof. This relies on Borg's successful traversal and the explicit `ctime,size,inode` file cache and `ctime` changed-file check to capture content edits, including a same-size edit whose mtime was restored. This daily proof independently checks the read-only snapshot UUID, the archive's UUID comment and immutable archive ID, and the previously accepted snapshot, archive ID, policy hash and full-proof time. It does not independently read all file content. If that chain is unavailable or due for a full proof, the drain uses the full proof. Existing archives never qualify for the producer-backed route because their creation result cannot be observed on retry.

The acknowledgement records `proof_mode`, `policy_sha256`, `full_proof_epoch`, the full proof's content digest, and the immutable archive ID. The policy hash covers canonical exceptions and the exact static Borg exclusion patterns after their bind-path qualification, so changing an exclusion forces another full proof. Producer-backed proofs also record the prior archive ID and prior proof digest. Pruning still checks the acknowledged snapshot identity and archive ID before deleting older local snapshots.

A fresh create logs `backup_phase=create`; every successful proof logs `backup_phase=verify`. The marker records creation time and Borg's logical original archive bytes, plus verification time, source bytes hashed, and archive content bytes verified. Content verification bytes are zero in producer-backed mode, which makes the difference from a full content read visible. Borg's logical size is not a physical disk-read counter.
